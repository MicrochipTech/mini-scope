## Button states

| State | Run, Probe | Abort | Connect, Start, Stop, Reset, Write, channel list | script list, Browse |
|---|---|---|---|---|
| not connected | off | off | on | on |
| connected, script selected, idle | on | off | on | on |
| run or probe starting (no session yet) | off | off | off | off |
| session exists, not yet aborting | off | on | off | off |
| after Abort or an abort cause | off | off | off | off |
| state `done` | as idle | off | on | on |
| port lost | as not connected | off | on | on |

The same function (`apply_busy`) runs in the click handler and in the page timer, so a second or reloaded page follows.

## Design points

- The GUI never sends during a run. The five paths that send (Connect/Disconnect, Start, Stop, Reset, Write) are disabled
  and also refused in the handler. Chart, CSV, PNG and Autoscale only read `snapshot()`. No timer sends. The GUI has no
  auto-reconnect. NiceGUI drops the events of a disabled element on the server, so the handler guards are a second layer.
- The stream of a script: event `channels` fills `app['active']`, `names` (with `[unit]`), `mode`, `period`. The values before
  the run are kept in `app['pre_run']` and put back at the end. The chart is emptied then, because the read-back of the
  safe end starts short streams that replace the data in `Scope`.
- Closing the browser: `app.on_connect` and `on_disconnect` keep the set of connected pages; a thread per run aborts after 5 s
  without a page (`GRACE_S`). Safe end, limits and heartbeat are unchanged.
- Process end: `app.on_shutdown(script_tab.shutdown)` (abort, wait up to 8 s) runs before `close_ports`. uvicorn runs it on
  Ctrl+C. A closed console window or Ctrl+Break does not reach it on Windows, so `SetConsoleCtrlHandler` calls the same
  `shutdown(4.0)` (events 0, 1, 2, 5, 6) and then lets the default handling go on.
- Port lost: result reason `port error: ...`, `RUN.lost`, the page calls `host.lost()`: port closed, "not connected".

## Not tested

- MDB and real hardware; other browsers than Edge.
- The `on_shutdown` path by Ctrl+C itself (Ctrl+Break through the console handler is tested; both call `shutdown()`).
  A closed console window (event 2) is the same handler, not tested.
- The handler guards alone: NiceGUI drops the events of disabled elements first, so a refused click was not seen.
- Reconnect after a lost port on SIM: Connect then says "port open, but no answer from target", most likely because the
  simulated target keeps streaming and `connect()` does not stop it first. Not investigated, existing behaviour.
- A reload while connected and idle loses the connection of that page (existing behaviour). During a run the new page adopts
  the Scope of the run. Two pages that share a Scope: a Disconnect on one closes the port for the other.
- Browse and Open (as in 4.1).
