# Card 6.2: customer data out of the reports, tools/report.py

## What changed
- `hw_check.py`: the file holds no ELF path (says `test.X production` or `custom ELF`), no port name
  (`SIM` or `COM`), no OS error text (`serial error`). It also writes `hw_report.json` with numbers per check.
- `doctor.py`: the file holds no root path, Python path, project macros, COM port description or hardware id,
  and no exception text (class name only). The console keeps all of it.
- `report.py`: allow list. Check names are fixed, numbers must be plain finite numbers, rule codes match
  `[EW]\d{3} x\d+`, everything else is dropped and counted.
- Fields in `mini-scope_report.txt`: python, os, mplab_x, xc_dsc, device versions; doctor: status per fixed
  check name, brg, baud_error_pct, fosc_mhz, scope_fp_mhz, com_port free/busy; hw_check: status per fixed
  check name with fp_factor, wrong, samples, lost, resyncs, period_us, depth, outliers, steps,
  clock_dev_pct, pretrigger, slope_ratio, answer_s; run_script: port kind, mode, status, rule codes with
  counts, three fixed check lines, abort wall_ms and target_ms, wall_clock_s. Not copied: script name, reason.
- Docs: TROUBLESHOOTING.md section 9, CLAUDE.md "Handing over" and the build output line, README.md,
  `.gitignore`. USER_GUIDE.md has no instruction to send files: unchanged.

## The test shown failing
`MARKER_LEAK=1 python tests/test_report.py` makes `report.build` append one input line (`script ZQMARK.py`)
to its output. Result: `FAIL markers in doctor, hw json and run inputs: none in the report`, exit code 1.

## What the test covers
Marker `ZQMARK` in: doctor lines (root path, user name, tool detail, device pack, device, COM port text,
macros, hint, exception text, unknown check name), hw json (port, python, unknown keys, string where a
number belongs, unknown check names, a NaN), hw text lines, run report lines (script name, reason, port,
status, rule codes, check lines, abort time, wall clock, traceback). Real runs: `hw_check --port SIM` with
`--elf` in a marker folder; hw_check through the ELF branch with marker variable names and port name;
doctor from a copy of the tree in a marker folder, with marker in PATH, USERPROFILE, HOME, MINISCOPE_VENV.
The doctor console does show the marker (positive control), its file does not. The path of this checkout,
the home folder, the Python path and the user name are also absent from the three files.
