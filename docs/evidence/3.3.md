## Interface

```

tune_check.record(path, table, ...) -> Recording(problems, calls, stopped) or None   # the dry run alone

tune_check.RULES = {code: (severity, stage, meaning)}      # 50 codes: 44 errors, 6 warnings
```

No import of `scope_gui`, no Scope, no target. Problems are sorted by stage, line, code and reported once per code, line and
variable. Line numbers point into the script.

## How it works

- Stage 1: `compile()` for syntax errors (E101). Undefined names by pyflakes (E102, E103). With `from tune_api import *`
  pyflakes only says "may be undefined, or defined from star imports". So the star import is taken out of the AST and
  `tune_api.__all__` is passed as `builtins` to `pyflakes.checker.Checker`. Suggestions by `difflib`. `main` and `check_idle`
  missing: E104, E105.
- Stages 2 and 3 share one recorder (`_Dry`). The script file is executed unchanged, but with its own `__builtins__` whose
  `__import__` answers `tune_api` with a private module object holding the recorder functions. So `sys.modules` and the real
  `tune_api` are never touched, no lock is needed, and a real run cannot reach the recorder or the other way round. The
  recorder has no Scope, so it cannot reach a port. The real API functions stay unreachable: they need a thread-local session.
- It runs on a daemon thread. Budget: 50000 API calls per function (main, check_idle), 5 s for the whole dry run. At the call
  budget the recorder raises a `BaseException`. At the time budget the caller sends the same exception to the thread
  (`PyThreadState_SetAsyncExc`), which also ends a loop without API calls. A script that swallows the stop is parked at its
  next API call; a call that does not return (`time.sleep`) is reported at its line and the daemon thread is left.
  W301 names the line and the budget. After a stop by time, `check_idle()` is not run.
- VarError rules map to E201 to E211. If the name is a string constant `VAR_X = "..."` in the script, the problem is reported
  at that line, otherwise at the call.
- `check_idle()` runs after `main()`. There `read()` accepts any variable of the ELF (the target is not streaming).
- The checks of `write()`, `read()` and the declarations follow `Session` (same texts where they exist).
- W204 is raised for every allowed variable without `safe_value()` at its `VAR_` line, W205 for every measured variable
  without `unit()`, both only after a `main()` that ended normally.
- Capture rules (E218 f32 trigger, W203 `limit()` in capture mode) are in the table and marked in the code
  (`# card 6.1`). Every name in `tune_api.__all__` without a recorder is recorded and answers 0, so card 6.1 only has to add
  the names to `__all__` and the rules at the marked place.

## tune_api.run()

Order: active-run check, `tune_check.check_script()`, errors raise `RunRefused` with `e.problems` (all problems, nothing sent,
no run folder), then the Session. Warnings go to the log and `run.txt` as `file:line: warning: text [W204]`.
`result['rule_codes']` is a dict code -> count of the problems of that run (no text, no names). Changes in `tune_api.py`
besides `run()`: `Session.rule_codes = {}` in `__init__`, the field in the result dict, docstring lines. Without a script
file, or with `hooks={'skip_checks': True}`, the checks are skipped. `tests/test_script.py`: `go()` adds `skip_checks`
by default (one line), one direct `run()` call gets the hook. Nothing else.

## The star import trap

Output of `test_check.py star`, script with `wirte(...)` and a mistyped constant `VAR_RAMPP`:

```
raw pyflakes on the unchanged tree:
  t.py:1:1: 'from tune_api import *' used; unable to detect undefined names
  t.py:10:5: 'expect' may be undefined, or defined from star imports: tune_api
OK   pyflakes alone reports no undefined name, only star import notes
OK   handled: mistyped function and mistyped constant are errors at their lines: [('E102', 23), ('E102', 24)]
OK   star handling switched off: no E102 any more (the test above would fail): [('E390', 23)]
```

With `tune_check.HANDLE_STAR = False` the static check finds nothing. Only the dry run still catches the first mistake, as a
runtime NameError (E390, line 23), and the mistyped constant not at all, because the run stops there. So the star handling is
what makes both errors visible at the right line.

## Not tested, deviations

- Stage 4 is not here. Capture rules wait for card 6.1.
- A script that swallows the stop in a loop without any API call cannot be ended; its daemon thread would keep running. A
  call that blocks (sleep) leaves a sleeping daemon thread until it returns.
- The dry run takes the time of the script, normally some 10 ms, so `run()` no longer returns quite "at once".
- The dry run executes the top-level code of the script and of any module it imports; a script that writes files itself does
  so in the dry run too.
- W204 counts allowed variables, not variables that `main()` really writes.
