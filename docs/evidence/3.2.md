## Entry points

```
s = tune_api.run(script_path, scope, table, on_event=None, out_dir='runs', elf_name=None, hooks=None)
s.wait(timeout) -> result dict or None; s.done (Event); s.result; s.folder; s.traces
tune_api.abort(reason) -> True if it was the first cause, False without a run
```

- `run()` returns at once. It raises `RunRefused` if a run is active, the script is missing or the folder is not
  writable. Then nothing reached the target.
- `on_event(ev)` gets dicts on a thread of its own: `state` (starting, trial, running, safe_end, done), `log`, `unit`,
  `table`, `row`, `trace`, `result`. The fields are at the top of `tune_api.py`.
- `result`: status (`ok`, `aborted`, `error`), reason, abort_ms, abort_ms_target, errors, folder, tuning_h,
  summary_channel, summary_text, summary_mark.
- `hooks` are for tests: `before_send(stage)` in `write()`, `hold_heartbeat` (Event).
- `build_id_check(session)` is the marked function for card 5.1, it passes.
- Script API errors: `ScriptError`. The stop of the script: `RunAborted(BaseException)`.

## Rules as implemented

- Abort flag: `Session.request()` sets it at once, from any thread, the first cause stays. The monitor thread then does
  the safe end: pass the gate, safe values twice by `write_many`, keep the stream (if there is one) 200 samples + output
  lag, stop the stream, save the open trace (`unfinished`), stop the script thread, read back, stop the heartbeat.
  Before `stream_start()` has passed `_refusal()` the safe values are skipped, see "Supervisor review".
- Race: `write()` rechecks the flag inside the gate lock. The safe end passes through the gate after the flag is set. So
  a write in progress is out before the safe values, and any later one sees the flag.
- Port calls of the safe end run on a helper thread with a time limit (`max(5 s, 2 s x time_scale)`), so a hanging port
  does not stop the end of the run.
- Abort time: abort cause to the return of the first `write_many`.
- `tuning.h` is written if and only if: the script returned normally, no abort, no error and no failed safe value
  read-back (`status == 'ok'`), `define()` was called, and no trace after the last `row()` is failed, invalid or
  unfinished. Without any `row()` all traces count. An invalid or failed trace or row of the sweep before the last
  `row()` does not block it. A script that returns after a failure has no `define()`, so no `tuning.h`.
- `results.csv` has a last column `status` (`ok`, `invalid`). A row is invalid if lost or resyncs rose since the last
  row. The trace status is in `run.txt` and in the `trace` event.
- `run.txt` lists the upper case constants of the script as parameters, written at `stream_start()`. The heartbeat is
  not logged per write.

## Decisions to check

- A run that ends before `stream_start()` has passed `_refusal()` writes no safe values, also on exception or abort: the
  ELF is not verified then, `build_id_check` lives there. The log says so. From that moment every end of the run writes
  them and reads them back, also during the trial. The script itself still cannot write before the trial has passed.
- The heartbeat stops after the read-back, not right after the safe values. Reason above.
- After the abort flag the heartbeat uses the scaled wall clock even if the stream still runs: a stalled stream must not
  stop it before the safe values are out.
- `write()`, `read()` and traces need a passed `stream_start()`. Declarations after it are refused.
- `Q15()` works outside a run, it touches no state.

### 2. `_finish` and the safe end are guarded

`_finish` builds a result with status `error` first and runs `_close_run` in try/except/finally: `result` is always a
dict, `result` and `done` events go out, `_active` is cleared, `done` is set. If `_close_run` raises after `tuning.h` was
written, the file is removed, because `tuning.h` exists only for status `ok`. Each step of `_safe_end` runs through
`_step`, so a failing step is reported and the next one still runs. `_stop_stream` stops the stream in a `finally`. The
heartbeat stop and `_finish` are in a `finally` of `_monitor`.

Tested with injected exceptions: `run_file.close()` (disk full), `_write_tuning`, `_save_open_trace`, `_keep_stream`,
`_stop_script`, `_verify_safe`, `_send_safe`, and `_drain` inside the safe end. Each: status `error`, the error in
`errors`, stream stopped, heartbeat stopped, script thread ended, no `tuning.h`, `done` set, `result` event sent, next run
starts.

### 3. Magnitude of `limit()`

No code change. Stream columns are float64: `Scope.start` sets each column to `np.zeros(0)` and `_stream` extends it by
`np.concatenate`, which promotes every integer type to float64. So `np.abs(-32768)` is 32768.0. Integer columns exist
only in `Scope._capture` (mode above 0), and `tune_api` always starts mode 0. The test stays.

Test `width` through a real stream on `SIM`, s8, s16, s32 at the address of `motor.kp`, on the old code alone, unchanged
now: `read()` gives -128, -32768, -2147483648, the column is float64, `limit()` of 127, 32767, 2147483647 trips with
`= -128`, `= -32768`, `= -2147483648`. A float NaN trips `limit()` too. So this test passed before the fix.
