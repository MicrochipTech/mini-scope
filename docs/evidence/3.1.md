## Public interface

```
VarTable.from_elf(path) -> VarTable           # does not raise for a missing -g, see has_debug
VarTable.from_symbols(symbols, types=None)    # symbols: name -> (address, size); types: name -> 's16' etc.
VarTable.has_debug                            # False: ELF without DWARF (or from_symbols({}))
VarTable.lookup(expr, require_ram=True) -> Var
VarTable.names() -> sorted list of str        # every name lookup() accepts (default require_ram)
Var(name, address, width, type, ctype, is_volatile, is_const, in_ram)   # namedtuple
VarError(rule, message, suggestions)          # .rule str, .message str (= str(e)), .suggestions list of str
```

- `type` is one of `s8 u8 s16 u16 s32 u32 f32`, the keys of `scope_gui.TYPES`. `ctype` is the C type name for display
  (`q15_t`, `uint16_t`, `enum signed_mode`).
- A plain number as `expr` (`0x1100`, `4352`): address only. `width`, `type`, `ctype`, `is_volatile`, `is_const` are None,
  `in_ram` is computed. Above 0xFFFF: `bad_address`.
- From `from_symbols`: `is_volatile`, `is_const` and `ctype` are None (unknown). Without `types` the type is the signed
  one of the width (like `scope_gui.DEFAULT_TYPE`).
- `require_ram=False` returns a variable in flash with `in_ram=False` instead of raising `not_ram`.
- `is_volatile` and `is_const` are the qualifiers of the whole path: `volatile struct motor_s motor` makes `motor.run` volatile.
- A static name that exists twice: the bare name raises `ambiguous`; `vars.c:counter` (file basename, colon, name) selects
  one. `names()` lists such names only in the qualified form. `Var.name` of the result is the qualified form too.
- Rules: `not_found needs_member needs_index index_range pointer bitfield width ambiguous no_debug not_ram syntax
  not_struct not_array bad_address unsupported`.
- `not_found` carries `suggestions` (difflib, case blind, best first, whole expressions such as `motor.state`).
  The message ends `- did you mean motor.state, ...?`.
- `names()` expands structs (anonymous ones flattened) and arrays, at most `MAX_PER_VAR = 64` names per top-level variable.
  Bit fields, pointers, 64 bit and flash data are left out. `RAM_END = 0x8000`: data space below it counts as RAM.
- Not covered: variables local to a function (`static` inside a function), arrays of pointers.

### DWARF 2 quirks found

- The compile units are DWARF version 2 (address size 4). `DW_AT_data_member_location` is not a number but an expression
  block `[0x23, n]` (`DW_OP_plus_uconst`, ULEB128), which pyelftools returns as a list. `DW_AT_location` is
  `[0x03, a0, a1, a2, a3]` (`DW_OP_addr`, 4 byte little endian), although data addresses have 16 bits.
- Bit fields carry `DW_AT_bit_offset` counted from the most significant bit of the storage unit (`ready` 15, `fault` 14,
  `level` 10 for a 16 bit unit). The code does not use it: bit fields are refused, the message names the storage word.
- Enums have no `DW_AT_type`: the sign is derived from the enumerator values.
- Const data gets flash addresses in the same address space (0x833E ... 0x834A), so `address >= 0x8000` is the test for
  "not in RAM".
- The ELF holds assembler compile units from the library (`divsi3.s`, `udivsi3.s`) with a foreign `DW_AT_comp_dir`. They
  hold no variables and are skipped.
