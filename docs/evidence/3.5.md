# Card 3.5: render_png and summary.png

## What changed

- `gui/scope_gui.py`, `render_png` only. New optional keys of `d`, all absent in existing callers:
  a series may be a 4-tuple `(name, x, y, style)` (matplotlib line properties), `legend: 'outside'`
  (legend right of the chart, the axes get 0.74 of the width), `ylabel`, `mark_row` (row highlighted),
  `empty_text` (centered text in a chart without series). The default legend is still upper right inside.
- `gui/tune_api.py`: `run(..., render_png=None)`, `Session._summary_data` (builds `d`), `Session._summary_png`
  (renders, writes `summary.png`), `result['summary_png']` (path or None), `Session.table_rows`.
  `tune_api` does not import `scope_gui`.
- `tools/run_script.py` passes `render_png=g.render_png` and prints the picture path. It already imported
  `scope_gui` as `g`; the page starts only under `if __name__ in {'__main__', '__mp_main__'}`, so an import
  does not start the GUI (checked by reading, and by the tests, which import it the same way).
- `tests/test_script.py`: `test_summary` (16 checks), `go()` got a `render_png` parameter.

## Behaviour

- Rendering runs in `_close_run`, after the safe end and the heartbeat join (those are done before
  `_finish`), before `run.txt` is closed and before the `'result'` event. A test checks that the file
  exists when the result event arrives.
- It runs on a daemon thread with a 30 s join (`RENDER_S`). An exception or a timeout is logged
  (`summary.png not written: ...`, in the log event and in `run.txt`), the result gets `summary_png` None,
  the run ends normally. A render that is still running after the timeout is abandoned, its output is dropped.
- matplotlib: `Figure` and `FigureCanvasAgg` only, no pyplot, so no GUI backend and no main thread needed.
- Picture: result line on top (script text for status ok, else `status: reason`, cut at 130 characters),
  line with script, port and ELF base name, line with channel, trace count, marked value. The summary
  channel of all traces overlaid from trace start, in the physical unit when `unit()` was given
  (axis `name [unit]`, else `name (raw)`). Failed, invalid and unfinished traces dashed. The first 12 traces
  and the first 12 rows; more gives a note under the table. No summary channel or no trace: empty chart with
  the reason in it. Marked trace: any trace whose title has the marked value as a word (black, thick).
  Marked row: first row with a cell equal to the value.
- Not requested but done: unfinished traces are dashed as well; the table has the status column of
  `results.csv`.

## Existing pictures unchanged

Rendered the same `d` (2 series, 2 cursors, table, notes; and a variant with note, no series, no rows)
with `render_png` of HEAD and the new one, compared the RGB arrays: both `identical`, 1920 x 1080.
Where a new option is used the picture differs by design.

## Pictures looked at

`docs/evidence/m3/summary_sim.png`: `tune_startup.py` on SIM, `tools/run_script.py --port SIM`, status ok.
Result line "Suggested ramp rate: 100, 5 of 5 starts confirmed" on top, then script, port, ELF line and the
channel line. Nine traces overlaid from 0 ms; the trace "ramp 100" is black and thick, "ramp 400 (failed)"
is red and dashed and lies flat at 0 rpm. The legend is right of the chart and covers no curve. Y axis
"motor.speed [rpm]", peaks about 550 rpm. Table with four rows, row 100 highlighted and bold, readable at
10 pt. The stamp at the bottom right touches the lower table edge (the same as in the GUI picture).
The confirm traces (same ramp value) are not highlighted, only the traces of the table row.

`docs/evidence/m3/summary_sim_abort.png`: the same script aborted about 3.5 s after the start
(`abort('test abort after a few seconds')`). "aborted: test abort after a few seconds" on top, one trace,
dashed (unfinished), legend outside, no table because no `row()` was reached. The legend entry reads
"001 unfinished (unfinished)": the title of an open trace is already "unfinished" (existing behaviour).
